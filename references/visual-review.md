# 独立视觉审查（强制）

每次改完 PPT 模式、重跑 zero shot、或交付一套 deck 前，必须另开一个**全新的子 agent**做视觉审查。审查者只读，不改文件、不重排、不生成 deck；它的报告是交付的一部分。

## 触发

- 模式/引擎改动后的 zero shot；
- 任何页面的返工（尤其 P2/P3/P5/P6）；
- 发布前。

## 审查者拿什么

- contact sheet（整套一眼看节奏/重复）；
- 每页全分辨率 PNG（不只看缩略图）；
- `spec.json` 与渲染输出（可对照页面任务）；
- 上一版页面（如果这次是返工）。

## 必查

1. **第一眼**：最强/最弱页；是否有“模板感”或“换皮卡”。
2. **对齐/重叠**：节点、箭头、标签、来源行、页码；有没有穿字、压字、贴边、空走线。
3. **机制图**：箭头是否有语义、分支是否闭合、阈值/状态/时间是否自洽；不允许“图上说 A、文字说 B”。
4. **字号**：低于 8pt 直接列出；8pt 但投影偏小的关键机制句也要列。
5. **重复**：同族版式、同一种卡片/流程、同一组配色是否连续出现。
6. **图片**：是否只当背景；图内标注是否和正文有对应；是否标“场景示意”。
7. **不可信内容**：无来源的数字、无对应的 01–04、把示意当实测。

## 交付格式

最多 5 条结论，每条带**页码 + 位置 + 具体问题**；最后给 3 个必须改。不要泛泛说“加强设计”。

## 纪律

- 审查者不改文件；修改由主 agent 做。
- 审查不过，不把版本说成“完成”，不发布。
- 审查报告要跟 deck 一起留在输出目录。


## 审查必须闭环（不是审完就结束）

审查发现的问题必须回到 `spec.json` 修改，再重建、再渲染、再开一轮**新的**独立审查；最多 3 轮，直到：

- 没有“必须改”项；或
- 只剩明确记录、且用户接受的次级问题。

每轮把审查结果落到 `visual_review_roundN.md`，deck 报告里写清轮次与状态。**审查不通过，不得把版本说成完成。**
