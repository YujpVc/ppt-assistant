# 独立视觉审查（强制）

每次改完 PPT 模式、重跑 zero shot、或交付一套 deck 前，必须另开一个**全新的子 agent**做视觉审查。审查者只读，不改文件、不重排、不生成 deck；它的报告是交付的一部分。

## 触发

- 模式/引擎改动后的 zero shot；
- 任何页面的返工（尤其 P2/P3/P5/P6）；
- 发布前。

## 审查者拿什么

- contact sheet（整套一眼看节奏/重复）；
- 每页全分辨率 PNG（不只看缩略图）；
- `spec.json` 与渲染输出（可对照页面任务）；
- 上一版页面（如果这次是返工）。

## 必查

1. **第一眼**：最强/最弱页；是否有“模板感”或“换皮卡”。
2. **对齐/重叠**：节点、箭头、标签、来源行、页码；有没有穿字、压字、贴边、空走线。
3. **机制图**：箭头是否有语义、分支是否闭合、阈值/状态/时间是否自洽；不允许“图上说 A、文字说 B”。
4. **字号**：低于 8pt 直接列出；8pt 但投影偏小的关键机制句也要列。
5. **重复**：同族版式、同一种卡片/流程、同一组配色是否连续出现。
6. **图片**：是否只当背景；图内标注是否和正文有对应；是否标“场景示意”。
7. **不可信内容**：无来源的数字、无对应的 01–04、把示意当实测。

## 交付格式

最多 5 条结论，每条带**页码 + 位置 + 具体问题**；最后给 3 个必须改。不要泛泛说“加强设计”。

## 纪律

- 审查者不改文件；修改由主 agent 做。
- 审查不过，不把版本说成“完成”，不发布。
- 审查报告要跟 deck 一起留在输出目录。


## 审查必须闭环（不是审完就结束）

审查发现的问题必须回到 `spec.json` 修改，再重建、再渲染、再开一轮**新的**独立审查；最多 3 轮，直到：

- 没有“必须改”项；或
- 只剩明确记录、且用户接受的次级问题。

每轮把审查结果落到 `visual_review_roundN.md`，deck 报告里写清轮次与状态。**审查不通过，不得把版本说成完成。**


## 审美与连线（必查）

- 每条关系从头走到尾：一条折线、一个终点箭头；拐角出现箭头/断头，必须改。
- 主色/辅助色/语义色分别用在哪；2×2 卡四色、语义色兼作普通卡底，必须改。
- 图注与画面一致；图片必须有信息角色，通用场景不能当证据。
- 四柱等权是否有分组/阶梯/对照隔断；没有就是版式问题。
- 不能用“投影差异很小/可接受”豁免已列出的审美必须改；豁免必须给度量或明确降级理由。

## 跨页节奏（必查）

- 先看 `skeleton` 再看 layout 名；不同 layout 名但同一 skeleton（编号列/左图右列/账本）算重复。
- 同一 family 全 deck 最多 2 页；出现两对重复（architecture×2 + evidence_grid×2）必须列“必须改”，即使不相邻。
- 下半页空版心 >1.2in 或 item 覆盖不足，必须列，不能用“密度 PASS”豁免。
- 同族版式最多连续 2 页；第 3 页还同骨架，直接列“必须改”。
- 图片主导页不超过 60%；机制页不能全是照片 + 卡片。
- 8+ 页至少 2 页可编辑机制图；检查是否有节点/边/回边或分支，而不是只有框和标题。
- 每个机制页至少要能回答“谁指向谁、失败走哪、证据怎么回写”。

## 硬门

交付/发布前必须运行：

```bash
bash <engine-root>/run_py.sh review_gate.py <output-dir>
```

- 没有 `visual_review_round*.md`：exit 2（zero shot 只是 draft）；
- 最新审查还有“仍需改/不通过”：exit 2；
- 只有最新审查“通过”才 exit 0，并写 `review_status.json`。
- `review_waiver.md` 仅用于用户明确接受剩余次级问题，不能用来跳过第一轮审查。

## 审查报告签名（硬格式）

每份 `visual_review_roundN.md` / `visual_review_final.md` 顶部必须带一个 fenced 块，由**审查者**填写：

```review-meta
{
  "reviewer_session_id": "session-审查者自己的 id",
  "builder_session_id": "session-构建者的 id",
  "status": "pass",
  "must_fix": [
    {"id": "M1", "status": "fixed", "evidence": "P03 回边已接"},
    {"id": "M2", "status": "waived", "evidence": "用户接受"}
  ]
}
```

- `reviewer_session_id` 必须存在，且不能等于 `builder_session_id`；相等直接 FAIL（自审不算独立审查）。
- `status` 只有 `pass` 才能过；有必须改就写 `must-fix`，下一轮再改。
- 每条 `must_fix` 只能 `fixed` 或 `waived`；`open` 没过完不能算完成。
- `waived` 必须同时有 `review_waiver.md`。
- 没有这个块，`review_gate.py` 直接 FAIL；主 agent 不能自己写这个块冒充审查者。
