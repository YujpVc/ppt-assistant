# 短提示词自动展开（默认合同）

用户只说“这些素材，生成这部分的 PPT”时，不追问，按下面默认执行；把假设写进 `design_brief_and_page_plan.md`，不阻塞。

## 1. 读源与定页

- 读源文件对应的那一节，按“开场—问题—三条主线—方案机制—验证—交付”拆。
- 默认 **5–12 页**：用户明确说“只做 5 页”时，严格 5 页；否则章节过渡 1 页 + 内容 7–11 页，源材料足够时优先 10–11 页。
- 每页先写一句结论，再决定版式；不要先套模板。

## 2. 默认风格

- 申报/基金/评审：`grant`；标题衬线、正文黑体。
- 先列 3 套配色（含 accent2/accent3 + 理由），手选 1 套；不要默认鼠尾草/深青/暖纸陶土。
- 章节页从 `chapter_band` / `chapter_split` / `frost_number_panel` 里选，先列 2 个候选。

## 3. 默认结构（可按源内容微调）

- P01 章节过渡
- P02 为什么难 / 现状缺口
- P03 现状/三条线，最好有共同缺口
- P04 总体机制：状态总线 / 三段接力
- P05–P07 三条主线各一页，至少两页是**可编辑机制图**
- P08 平台/本体/接口（有产品图就抠图或参考图生图）
- P09 验证与指标
- P10 创新与交付

### 如果用户明确“5 页”

固定用这条叙事链，不要临时发挥：

1. P01 封面：标题 + 本体图/场景图；
2. P02 问题与现状：三种时间尺度 + 研究现状表/矩阵；
3. P03 总体机制：任务状态账本 + 节点/边/回边/分支，这是唯一必做的复杂机制图；
4. P04 平台本体：能力—状态表 + 本体图 + 调用链；
5. P05 验证与交付：四级验证/指标口径 + 交付带。

5 页版本至少 1 页 `"mechanism": true`；不能 5 页全是表/卡。

## 3.5 每页声明 skeleton

- spec 每页必须有 `"skeleton": "..."`，例如 `numbered-columns / left-image-right-columns / state-ledger / chain / timeline / table / split`。
- 同一个 skeleton 全 deck 最多 2 页；两对重复 FAIL。
- 不同 layout 名但同一 skeleton（P03 四栏、P04 三栏、P10 四栏）算重复，必须换骨。
- `rhythm_check.py` **所有页**缺 skeleton 直接 FAIL（5 页也一样）。

## 4. 机制图纪律

- 5 页至少 1 页、8+ 页至少 2 页可编辑机制图；该页 spec 必须写 `"mechanism": true`，节点/边/回边/分支至少有一项，不是“框 + 标题”。
- skeleton 只是骨架签名，不负责画流程图；复杂流程图必须落到 custom builder 的节点/边上。
- 同族版式最多连续 2 页；图片主导页 ≤60%；照片不能替代机制图。
- P06 这类验证页必须有半幅/竖切大图或整幅证据带，空白版心 ≤1.2in。

## 5. 图片

- 用户给了本体/产品图：既作为生图参考，也抠一张做平台页；其余场景图可自主生成，标“场景示意”。
- 每页 1–3 个语义图标，指向机制；不用 emoji 堆。
- 图片内容页 ≤55%；不允许整页只有照片和标题。

## 6. 门禁与审查

```bash
rhythm_check.py spec.json
density_check.py spec.json --strict
quality_check.py deck.pptx
review_gate.py output/
```

- zero shot 只是 draft；至少 1 轮独立审查，签 `review-meta`，reviewer≠builder；有必须改就回写→重建→再审。
- 审查不过，不说完成。
