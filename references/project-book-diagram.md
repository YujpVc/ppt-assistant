# 项目书技术路线图：通用制作规范

本文档是可跨项目复用的直接制图方法与视觉规范，与[项目书技术路线图：审图模型与 HTML 重绘流程](<审图模型全图转HTML重绘流程.md>)并列。可直接按本文制作，也可独立采用模型探索后重绘的方法；二者不存在先后依赖。

**固定视觉风格，不固定内容或版式。** 正文、素材、图号、画布比例、模块数量、布局、工具位置与输出位置均来自当前任务，不能从某次实验继承。用户当前要求优先；示例只是可选方法，不是默认模板。

> **执行优先级**：先按当前正文提炼关系、按目标插入尺寸分配字号和空间，再画机制，最后连接与导出。下文是验收依据，不能用“已加入照片/楷体/时间轴”几个形式条件代替完整验收。重复概述、第四个重复中枢和无语义小图优先删除，给真正机制腾空间。

**交付前先对最终 PNG 做四项否决检查：**（1）主路径实际连接内部节点而非容器边或空白；（2）模型探索中有用的机制在重绘后仍可辨，不退化成纯文字框；（3）所有字和子图留在安全区域，不能把图形塞在框外充数；（4）在目标插入宽度下，关键标签无需放大即可读。任一失败，先改几何与信息组织，不得用基础脚本 PASS 结束。

## 0. 执行前预算与完成门

本节优先于后文示例。先在本次任务记录写出阅读预算、两种不同构图及选用理由、图片语义分布、连接表，再开始绘制。不以日志声称已检查代替实际测量和打开渲染图。

- 字号换算：最终磅值 = SVG 字号 × 插入宽度毫米 / 画布逻辑宽度 × 72 / 25.4。反算 SVG 字号 = 目标磅值 × 25.4 × 画布逻辑宽度 / (插入宽度毫米 × 72)。用程序代入实际值，并核对最终 SVG 所有文本的真实字号，不能只写预算。例如逻辑宽 1200、插入宽 160 mm 时，8 pt 对应 21.17 单位，7 pt 对应 18.52 单位；这只是换算示例，不能继承为固定画布。关键正文目标约 8 pt，必要短标签不低于 7 pt；方法旁注同样按阅读尺寸预算。若超预算，删减重复内容并改变分区，禁止整体缩小、堆十余张文字卡或以高分辨率证明可读。HTML 的打印纸张应与本次插入尺寸一致。
- 图文分工：在各研究区域安排有语义、主体可辨的对象图和可编辑机制图。多对象实验内容的图片分散到不同机制区；不要为了凑数量强设六个图片区。图片先分配独立矩形区域，文字后排，不得覆盖文字、越过容器或被图标遮挡；不在图片下添加对象说明小字。
- 机制完整且不重复：只画本章支持的关系，层级图保留阶段—子任务—原子操作；持续时间/允许窗口用真实区间而非几个圆点表示。闭环在全图表达一次，不重复设置状态环、更新卡和底部同义流程；无可行计划才进入冲突核查，不把冲突画为每次更新必经阶段。
- 端点依据：跨区流接内部真实节点的轮廓或明确的小输入输出端口，绝不是容器外框，也不是进入卡片内部的蓝点。箭尖停在目标轮廓外小间隙；禁止穿框到内部接收点。连接表从绘图时使用的实际边记录导出，含源目标节点、端口、线型和路径；不能单独手写与源码不一致的声明。
- 自动检查范围：能测量时使用浏览器 SVG getBBox 检查文字是否越出安全内框、图片矩形是否覆盖文字矩形，并核对连接表端点。文字框超出圆形安全区同样失败；不能用裁切/隐藏越界字掩盖问题。检查失败须改源并重新导出。基础 XML 检查仍不等于视觉审阅。
- 最新成品冻结后，主 agent 打开整图和目标阅读尺寸图，独立 agent 再复核同一稳定版本。任何坐标变化使上一份视觉结论失效。未完成模型构图探索、审图或尺寸检查，记录真实缺口，禁止宣称完成全流程或一次生成成功。

## 1. 明确本次输入与交付

先读取当前对话提供的稿件、素材目录、附件和修改意见，实际查看相关素材，不凭文件名选图、不重复索要已有信息。新 agent 开始前核对唯一正文与目标章节；输入不完整时先核对，禁止自行换用其他项目全文。明确图的用途、必须表达的关系、目标插入尺寸和交付格式；只对影响内容正确性或交付的缺失信息提问。

- 不预设横向半页、固定像素尺寸或固定插入宽度。根据投放位置确定宽高比，再按最终插入尺寸检查字号、线宽和图片细节。
- 不预设三条主线、固定图号、共同验证栏或指标区。流程、反馈、分支、验证和约束均须由本次正文及用户要求支持。
- 不默认增加 PPTX 等格式；按任务交付。若要求原生可编辑 PPTX，文字、节点、连线、机制图必须是可独立编辑的对象，照片可替换；整图截图或整张 SVG 不等于原生可编辑 PPTX。
- 输入与输出路径作为本次参数，在任务目录说明中记录；共享规范和工具不写死任何用户主目录、素材名称、正文或坐标。

## 2. 从研究内容推导版式

先建立简明的“内容—图形—连接”清单：各模块要解释什么，输入输出是什么，关系是顺序、并行、层级、映射、反馈还是条件分支。保留关键术语和科学含义，短标签放图内，完整解释留正文；不把整段文字拆成一排框。

再根据关系、信息密度和最终尺寸选择版式。横向链路、纵向层级、中心辐射、不等宽主次区、时间轴或混合布局均可；不预设“上总下分、三列、底栏”的骨架，不要求每条主线都采用照片加子图。系列图统一风格，布局可以不同。

图形应解释机制。可按实际内容选择神经网络、去噪过程、映射关系、依赖拓扑、状态迁移、时间窗口、空间关系或其他示意；不按项目固定组件组合或数量。抽象方法不必强塞照片，能用图形说明的关系也不应退化成文字表格。无依据的闭环、装饰图标、泛化短语和空框不能补足内容。

验证、评价指标、曲线和数值仅在本次内容及任务需要时呈现。没有数据时不得伪造实测结果、训练表现或统计信息；概念示意明确其性质。没有正文依据的具体天数、阶段时长和观测时点也不能补写，时间轴可用正文支持的相对阶段。

## 3. 固定视觉风格

以下为默认风格，可由用户本次明确要求覆盖。版式和内容不属于固定风格。

| 项目 | 规范 |
| --- | --- |
| 基底 | 白底，黑色或深炭黑文字与边界；朴素工程科研风格 |
| 大区块边界 | 包含完整流程或内容的大容器采用直角、黑色实线；存在总括关系且确需边界时可用黑色虚线框，不强制设置顶部总括区 |
| 线宽 | 常规边界以 `1.5` 个 SVG 逻辑单位为基准，主流程约 `2–3`；按最终尺寸统一换算，不能将某次画布的像素值机械套用到所有项目 |
| 主体配色 | 分区表头或重点底色使用科研浅蓝 `#B4C7E7`，主流程箭头使用深工程蓝 `#2F5597`，其余用白、黑、灰和必要的浅蓝淡底；不要求每个模块都设表头，不自行加入绿/橙等分类色；照片保留自然色 |
| 线型 | 主流程用蓝色实线；条件、候选或不确定关系可用灰色虚线；图内含义统一，不能混用虚线边界与虚线流程的语义 |
| 字体 | 一级标题用黑体/雅黑，方法引导语用楷体，图注与说明用宋体，数学变量用衬线字体；运行时核实本地字体及替代后的渲染 |
| 内部组件 | 可用圆形、适度圆角、直角、时间轴、折线等；按语义选形，不把全部内容装进同一种矩形 |
| 禁止项 | 阴影、渐变、莫兰迪彩色卡片、装饰性图标和胶囊标签；不靠装饰替代科学内容 |

保持对齐、层级、留白与图文比例。避免文字堆积和无用途的大面积空白；删减重复解释后重新分配空间，不能靠缩小字号掩盖拥挤。

## 4. 素材方法

实际检查当前项目素材后决定是否采用，不绑定任何特定照片、设备、物种或文件名。真实实验照片仅做不改变科学含义的裁切、缩放和格式转换；不得修改样本数量、颜色或实验结果。

对于可替换的场景示意，优先避免系列图反复复用同一原图，可使用原始素材启发后重新绘制或生成。确有素材缺口时优先检索贴合主题的公开来源，找不到合适素材再生成；真实实验结果不能被生成图替代。记录来源、用途、裁切及“公开参考/生成示意/实拍”性质，不在图内堆来源编号。

综合路线图不应只由 SVG 线框组成。若正文涉及机器人、培养容器、培养设备、样本或实验场景，按正文所涉对象安排分散且可辨认的实拍风格局部图片（公开素材或单独生成的场景示意）；多对象实验路线不能只保留单一图片区，再用 SVG 绘制网络、时间轴和状态关系；照片承担对象质感和空间语境，矢量图承担可编辑的科学关系。图片应作为局部模块嵌入，不生成一张带大量文字的整图，也不把生成示意误写成真实实验结果。

需要保留对象身份时，可将 1–4 张对象级素材上传给参考图生图工具，让模型基于参考重新构图；不要把旧整图当作版式模板，也不要在提示词中声称“参考图”就等于已上传。参考图只提供主体、材质和设备特征，生成结果仍须检查结构、比例和科学合理性。

只有需要的素材副本进入本次任务目录，保留用户原文件。HTML/SVG 的交付资产应离线可用，嵌入实际使用的图片与样式，不依赖临时服务、失效外链或占位图片网站。

## 5. 可编辑绘制与箭头

优先复用任务已有工具。文字、几何和箭头适合 SVG/HTML 或其他可编辑矢量工具；需要计算绘图时再用 Matplotlib 等，不把某种库设为必经步骤。照片保留为位图，不宣称整图完全矢量。

- 先定义节点几何，再计算连接端口。矩形按选定边的法线进入；圆形和其他形状按真实轮廓求交，不直接连中心。
- 箭杆接在箭头三角形底边中央，底边垂直于末段。箭头尖端在目标轮廓外保留一致的微小间隙，不进入方框、文字或图片，也不接到框角或箭头斜边。
- 正交线、直线或曲线按机制和空间选择。折线避开文字、图片与节点；反馈和旁路分配清晰通道，汇合点不得打结。
- 用 SVG marker 时核对 `refX`、箭头长度和缩放后的实际尖端位置；源路径终点不一定就是可见尖端。
- 复杂图可保存节点、端口和连接数据辅助检查；数据格式由任务实现决定，不强制依赖某个项目的 JSON 或硬编码坐标。

## 6. 导出、审图与返工

按本次所需格式导出，并从同一有效源文件更新各格式。HTML 打印尺寸由当前画布与目标插入尺寸设置；不得把旧项目的 CSS、纸张尺寸或三列坐标复制成通用工具默认值。

执行最小充分的结构检查：格式能否解析、资产是否可用、标签是否齐全、页数与尺寸是否符合本次任务。图内几何和碰撞检查仅在相应数据与工具支持时执行；准确说明检查范围，不把基础检查通过说成全面排版通过。

必须查看最终渲染的整图、实际存在的密集区域、关键箭头和图片裁切，并按最终插入尺寸检查可读性。对表格、状态卡等检查文字、圆点、边界和内边距；对反馈/恢复路径检查方向、端点和线路。发现问题回到源文件修正，重新导出并复核相关区域。复杂图按当前任务的委派要求请独立审图 agent 返图；未做的检查不能声称已通过。

若交付原生可编辑 PPTX，另查对象结构并实际渲染；无法渲染时明确只完成结构检查，不以 PDF/SVG 预览代替。

### 返工时的空间与引线处理

- 调整模块高度时要同步移动外框、表头、节点、说明、图例和连接端口；只移动文字会留下新的空洞或造成局促。
- 上部模块留白过大、下部模块拥挤时，优先重新分配模块边界和内部纵向层级，再微调字号。时间轴、事件卡、状态卡和图例应按同一条垂直节奏排列。
- 图片标注线必须从实际对象的清晰位置出发。不同对象使用独立通道，不共享横向母线；标注顺序按目标位置安排，避免交叉、回折和穿过图片文字。
- 反馈、回写和恢复线路使用侧边旁路，目标接入卡片边界的中部或底部；不要压住表头、说明文字或下一个模块的边界。
- 机制图中的连接线不能穿过标题或节点标签。必要时在文字两侧断开连接，或先用与底色一致的遮罩留出文字间隙，再从节点边界继续连接。
- 每次返工后都要重新查看整图和关键局部；严格审图 agent 应以最新渲染图复核，而不是只看旧截图或源代码。只有源文件、PDF/PNG 和可编辑交付物同步更新后才算完成。


## 7. 通用工具与项目资产

迁移包必须覆盖真实运行链路：网页、服务端、客户端、启动脚本、依赖和配置模板都要齐全。只带调用客户端不能称为开箱即用。经验库只保存无密钥工具与模板；用户个人开箱包可迁移其现有本地配置，并明确包内含凭据。跨目录解压后验证启动、网页、接口上传、上游转发和结果下载；本地健康检查、模拟接口和真实生图结果分别报告。


工具入口：[README](<技术路线图_审图模型重绘/README.md>)。工具接收路径、服务地址、模型、画布等本次参数；网页预置已测模型并允许手动输入模型 ID，命令行通过 `--model` 选择；不内置项目文案、素材、布局或凭据。不预建固定版式生成器；确需复用的机制组件再按真实任务提取。

经验库仅存通用规范、工具与依赖说明。正文、素材、提示词、模型输出、排版脚本、坐标、成图和审图意见留在本次任务目录。目录结构随任务组织，保持来源清楚、源文件可找到即可，不要求所有项目复制同一目录树。

交付时简要说明成图及源文件位置、实际执行的检查、素材性质和未解决的限制。不擅自删除原始文件或无关历史产物。

迁移、重命名或移走服务目录后，应从新包重新启动服务并更新本次客户端地址；旧进程可能仍响应健康检查，却因保存路径失效而丢失生成结果。迁移验收至少完成一次真实生成、落盘及下载，不能只以端口可访问判断可用。遇到 HTTP 500 时先区分本地文件保存错误和上游模型错误，再决定是否重试。

## 8. 可复用执行提示词

> 根据本次对话提供的正文、素材、用途、尺寸与交付要求，制作并实际渲染技术路线图。先理解内容关系，再自由设计布局，不继承任何示例项目的图号、三列骨架、底栏、素材或坐标。保留本规范的字体、浅蓝/深蓝配色、实虚线语义、线宽层级和直角大区块风格，内部组件按机制灵活设计。缺素材先检索，必要时生成示意，不伪造实验结果。箭头由节点轮廓和端口计算，箭杆连接三角形底边中央，尖端停在目标轮廓外。导出所需格式，查看整图、关键局部与实际插入尺寸；修正后重新渲染。所有路径和内容作为本次输入，通用工具不写死项目数据。报告真实完成的检查与限制。


## 9. 端到端复盘清单

每次新图或整组图交付前，按以下顺序复盘，避免“局部修好但整体退化”：

1. **内容**：从正文列出模块、输入输出、顺序/并行/映射/反馈/条件关系；删除没有正文依据的闭环、指标和装饰性结论。
2. **素材策略**：整图构图探索默认不上传旧整图；局部场景可上传 1–4 张对象级素材让模型重新构图。参考图只提供主体和材质特征，不等于实验结果，也不应直接成为最终图。
3. **版式**：先按信息密度分配模块边界，再布置图片、机制图、时间轴、卡片和说明；删减文字后重新分配空间，不能只缩字号。
4. **绘制**：文字、节点、机制示意和箭头保持可编辑；同一系列使用统一字体、配色、线宽和实虚线语义，内部组件按含义灵活选形。
5. **连接**：所有箭头从节点轮廓端口计算，箭杆接三角形底边，尖端停在边界外；标注线独立分道，反馈线走旁路，线路不得穿字、进框、接斜边或打结。
6. **渲染**：从同一源文件更新 SVG/HTML、PDF、PNG 和可编辑 PPTX（如要求）；检查页数、尺寸、图片比例、字体和离线资产。
7. **审图**：打开最新整图，再放大密集区、箭头端点、图片裁切、表格/状态卡和回写线路；独立审图 agent 只依据最新渲染图复核。任何坐标或文字变化都要重新审整组图。
8. **归档**：项目目录保留提示词、参考图、请求记录、生成结果、素材说明和源文件；经验库只保留通用方法与无密钥工具，不写入项目路径、API key、固定素材或特定坐标。

## 10. 生成前设计门（防止退化为纯流程图）

### 实物图分布门

综合实验路线图中，图片数量和位置按正文机制分配，不以“嵌入过图片”作为通过条件。若正文同时涉及样本/容器、机器人操作、培养设备、状态观测或执行证据，应在至少两个不同机制区设置可辨认的对象级局部图，并让图片承担不同语义；不得把两张图并排压在同一输入栏后声称具象化完成。每张图都要在最终 PNG 中能辨认主体，不能缩成角落缩略图或被文字卡片包围。

图片分布完成后，重新检查图文比例：如果缩小到目标插入宽度后仍是一眼可见的文字框和箭头堆，必须删减重复说明、扩大对象图或重画机制图。对象位图承担材质和场景语境，网络、映射、层级、状态迁移等关系仍由可编辑 SVG 表达；不能用多张无语义照片替代机制，也不能只用一张照片承担全图的具象化任务。

在开始 HTML/SVG 重绘前，必须把正文关系转成“结构 + 具象机制”的设计草图。下面是通用验收门，不是固定版式：

- **机制覆盖**：按本次内容从神经网络/文本解析、映射或拓扑、设备/容器/机器人、时间轴/事件记忆、状态迁移/恢复、培养周期/对照等类别中选择足以覆盖主要研究机制的图形；综合技术路线图通常需要多类，简单单一机制图不强加数量；图形必须解释正文中的对象、过程或关系，不能用装饰图标充数。
- **图文比例**：每个主要模块先保留一个可识别的具象区域，再放短标签；同一模块内的说明尽量不超过两行，完整解释回到正文。若一眼看过去主要是文字、矩形和箭头，必须回到版式设计阶段返工。
- **禁止固定骨架**：不得未经比较就套用“三个等高横向大框 + 底部验证栏”或其他历史项目骨架。允许中心辐射、左右协同、时间轴、环形反馈、不等高分区和混合布局；由本次信息密度决定。
- **字体可见性**：方法引导语、过程短句和机制旁注使用运行时核实的楷体（例如 `AR PL UKai CN`、楷体或 KaiTi）；一级标题使用黑体/雅黑，正文与图注使用宋体。渲染后必须能在整图中辨认楷体层级，不得只在隐藏或极少量文字中声明楷体。
- **字体实现**：若 CSS 定义 `.kai`、`.sans`、`.serif` 类，SVG 文本必须写 `class="kai"` 等类名；`font-family="kai"` 只是把 `kai` 当作真实字体名，不能证明楷体已生效。交付前搜索源文件，排除把 CSS 别名误写进 `font-family` 的情况。
- **图题隔离**：图号和正式图题属于正文排版，不写进成图；成图底部只保留正文确需表达的结论或验证信息。
- **素材策略**：实验对象需要实拍风格图片时，先查当前输入，再检索或单独生成局部对象/场景；不得用对象线框替代这一要求。抽象机制继续用可编辑图形表达，不生成带大量文字的“成品流程图”替代重绘。
- **语义复核**：机制图中的顺序、对象和反馈必须回到正文核对；网络节点的连线不能暗示未经正文支持的先后关系。时间轴、标注线和反馈线应避开文字，反馈接入节点边界中部或专用端口，不能落在角点。
- **视觉复核**：把模块改成不等宽或不等高仍不足以证明版式自由；复杂路线图至少要有一种跨轴关系（中心协同、环形状态、时间轴或侧边反馈）承担主要语义。任何引线不得穿过时间标签、节点文字或验证图形，底部结论文字与图形之间要有明确空隙。
- **模块内节奏**：表头下方必须保留稳定的内边距；时间轴的标题、刻度和事件卡不能进入表头带，刻度文字与轴线/引线之间留出独立隔离带。右侧状态区与时间轴要分栏或分层，不能把所有信息压在同一水平线。

完成初稿后，用以下问题自检：缩小到最终插入尺寸，是否仍能看出正文要求的主要机制？是否存在一块区域几乎只有文字？是否仍能认出历史项目的固定上下三块骨架？若第一项为“否”，或后两项为“是”，不得进入交付检查，先返工源文件。

### 返工补充：小型机制图与长反馈线

- 菱形、圆形等非矩形节点的文字必须完全落在安全内框内：先按最小内接区域排版，再画边界；文字不得接触斜边、圆周或箭头。
- 事件卡、证据卡等带两行文字的节点，应把连接端口设在边界中部或专用空白端口；不得把回写线接到右下角、斜边或文字所在区域。
- 跨模块证据/反馈线应沿独立侧边通道回写，避开下方模块底边和验证区；若线路必须跨越多个模块，先画通道再布置节点，不能让一条长线贴着卡片底边穿行。
- 生成 agent 交付前须确认文件写入已稳定，再由审图 agent 只审最终 PNG；同一轮若源文件仍在变化，审图结论无效。


### 连接与图片的可见验收

- 图片与矢量图各有独立占位，不能把旧的设备线框叠在实拍风格图片上遮挡主体；对象标签与实际主体对应。图片必须离线嵌入，缺图应明确报错，不能静默换回线框。
- 先按箭头实物长度分配节点间隙：可见箭杆至少容纳一个箭头头部长度，不能用几乎只有三角形的超短箭头充数；marker 应显式控制单位、尖端位置和尺寸，避免随 stroke-width 意外放大。
- 逐条从源节点追踪到目标节点；不允许从空白处发出或终止在空白处的悬空箭头。圆形端点按圆周求交，斜边端口按轮廓求交，不能凭目测连到附近。
- 反馈线不得纵穿时间轴、事件卡或表头，不得与说明文字叠线；主流程和反馈应有明确主次，长距离旁路线不能成为整图视觉主体。
- 中心闭环若只是重复各模块的输入输出，应删去重复的大圆和说明，直接用主要研究模块表达闭环。不能为了打破三栏再增加一个占据大面积的第四个流程模块或未经正文支持的“中枢”。
- 比较至少两种不同的整体构图后选择，由正文关系决定。保留比较结论于本次项目记录，不在经验库保存候选坐标。最终图必须同时满足内容完整、照片与机制图分工、字体可读和连线清楚，而不是只满足有照片、有楷体的数量要求。


**素材真实性门**：生成图片必须在项目记录标为“生成示意”，不得在图内写来源，也不得把插画/线框称为实拍；若用户要求实拍风格，必须检查纹理、光照和真实设备比例，未达到时应报告限制。

### 从失败样稿进入新一轮

#### 内容与构图验收，优先于形式检查

先分配阅读空间再绘制：按实际插入宽度换算正文和方法旁注的字号，综合路线图以可辨认正文和机制为优先。正文宜达到约 8 pt，重要标签不宜低于正文；版面不足时精简重复表述并重组图形，不把全图缩到小字硬塞。记录本次最终插入宽度、最小正文大小及换算，不以导出 PNG 像素高替代可读性。

每个主要区域先安排机制图和对象图的面积，再放短标签；解释回到正文。整段研究方案不能分装成十余张文字卡；树状层级必须实际画成树，候选映射必须画出对应关系，允许时间窗必须有可视区间，事件必须有相对时序，异常影响须展示保留和受影响的依赖。图形不是段落的背景。照片不得缩成边角缩略图；若用户将图文并茂作为验收要求，主要研究模块应有清晰的对象场景或机制视觉主体，而不是在验证区放两张照片应付。

闭环线先规划通道并用少量转折连接，不把恢复、证据、待核验与候选映射全挤在同一中心区。任一线路若跨过其他节点、字行或多个其他箭头，应重新移动分区与节点。用可辨认的短标签表达必要关系，不能靠图底部追加一整行“主闭环：……”补救缺失路径。

黑色直角大区块、浅蓝表头和深蓝主流程仍是既定风格。蓝色圆角卡片、阴影、装饰环带、贯穿全文的蓝色边框不是替代风格。图内不得出现十六进制配色、字体名、渲染参数、版本说明、制图备注或“生成示意”等实现内容；这些留在项目记录。最终审图先核实这些肉眼可见的要求，再运行结构检查。

先在任务记录中写清唯一有效的正文文件及图所在章节。只提取该章节的研究主线；不得转而解压另一份全项目正文，或把相邻章节、整个项目架构替代本图内容。每个主模块、标签和恢复步骤必须对应本章语句。绘制前列出“正文术语—可编辑机制—真实连接”的简表，渲染后再核对一次。

若本次输入给出质量标杆，实际打开它，比较可辨认机制的丰富度、对象图片的比例和最终尺寸下的可读性；质量标杆不是版式模板，不上传给整图生图工具。若没有标杆，从本次正文确定足够的机制密度。不能通过加大空心圆环、放大四个文字卡片、把主框错位或拉长反馈线冒充丰富的机制图。

构图先放机制：层级任务用有父子分支和先后关系的拓扑，候选映射用需求与能力之间的多条关系及选中路径，事件记忆用来源明确的事件轴与检索，异常影响用已确认/受影响节点的依赖子图。仅在正文支持时采用这些表达，不把它们固定为每张图的组件。照片与机制各有可读面积；对象图片必须符合本次研究对象，不能用不相关的机器人展台或普通装置充数。

主信息流必须连通内部真实节点，不能接大容器外框或空白。若需要校验，实际经过校验节点；旁注不代替箭头。大环路不能代替各模块内部的机制表达；主路径不能依靠最后一行文字才成立。图片下方不写对象说明、来源或“生成示意”，素材性质写项目记录。未达到这些要求的版本保留为失败样稿，不称为可交付。

重复出现的失败说明设计方法没有改变，不能只追加口头要求。动笔前在本次任务记录中完成以下三件事：

1. 画两种轮廓明显不同的构图草案，按关系清晰度、图文比例和最终尺寸选择。若上一版因“三等高框加底栏”被否决，下一版不能以同样轮廓加一张照片重交；无需给每条主线设置相同容器或表头。
2. 写清主要机制如何可视化。层级须看得出父子分支，约束须看得出候选与可执行对象，恢复须看得出影响范围与保留部分；几个等大的圆、加号盾牌、文字符号箭头不能代替这些关系。总览只需表达机制骨架，不必塞入方案细节。
3. 先画正文关系的简明语义图，再记录每条连接的源、目标、端口和线型，按节点实际轮廓计算可见尖端；跨模块连接接内部真实节点或明确的模块输入输出端口。模块外框旁、节点附近和两节点之间的空白均不算端口；校验节点不能画成执行后的可选装饰。没有箭头语义的文字关系不必强加箭头。确认主模块之间存在真实信息流，而非各自在框内自循环；条件分支保留原因到处置的方向，恢复路径若须校验或授权，必须实际穿过并连接校验节点，不得只用文字承诺。反馈线的源端和目标端都要落在真实节点边界，不能在两个大框之间结束。任何能通过箭头读出的路径都须有正文依据。

文字应先测量再确定小节点尺寸，尤其注意全角标点和中英文混排。图片裁切后要重新辨认主体：若抓持的器皿或机械臂关键部分被裁掉，调整画幅或改用完整显示，不能只确认图片文件已嵌入。


### 闭环与时间轴端点专项
- 正文要求闭环时，主路径必须回到规定的起点。执行类闭环不能遗漏“执行 → 结果证据”；不能只画证据向后流动而缺失执行回写。具体节点与校验顺序由当前正文确定，不固定模块名称或数量。
- 时间轴或验证链的箭头从源节点轮廓连接到下一节点轮廓，不能止于两节点之间的空白。用于连续时间方向的轴线除外，应明确区别轴线与节点关系。
- 端口表必须与最终 SVG 实际路径一致；若源脚本和渲染结果不一致，以最新 PNG 重新审查，不得沿用旧端口声明。
- 模块布局拥挤时，重新分配主机制的面积并预留跨模块通道。先计算文字安全区域和端口，再绘制连接；少量有依据的主要节点优于反复叠加概述框。结构修复和全新独立生成分别记录，不将主 agent 接管修图当作开箱包一次生成通过。

### 对标、返工与依赖语义复核

- 实际打开质量标杆，比较机制表达、图片主体、视觉重心和最终阅读尺寸。新增照片、楷体或时间轴的数量不代表超越标杆；重绘不能丢掉标杆中有正文依据的语义编码、层级分支或先后依赖。照片不能替代机制，状态词不能替代依赖子图。
- 同类问题反复出现时，改变局部节点排布或机制结构，重新分配通道和文字面积。不要固守错误坐标，只挪端点、再造短 U 形回折或不断追加规范；两种构图的比较必须体现在实际几何中。
- 逐条追踪真实有向路径。需要校验的流实际经过校验节点；恢复需能区分已确认事实、受影响的未执行后继与调整路径。图示的源、目标须与正文及连接表一致，不能把指向另一节点的箭头只在记录中改名。
- 冲突只在无可行方案等正文规定条件下反馈，不能成为所有更新的必经步骤。反馈和主流程使用独立端口，反向箭头不能共用一个端点。

### 几何、字体与稳定版本验收

- 按最终 SVG 的全部实际文本节点核算字号，计入 CSS、内联属性及缩放，正文、旁注、刻度分别检查。打印检查必须来自同一最终文件，记录插入尺寸与导出比例；不能只复制高清图改名冒充另一种尺寸验证。
- 测量文字完整边界后再定节点与内边距；公式末尾、跨栏长句、时间轴行标签和非矩形节点文字均须留在各自安全区。分隔线、照片和线路不能压入该区；不能靠裁切、缩字或白色遮罩掩盖问题。
- 节点、端口、绘制路径和连接表共用数据源。每条边记录源目标、命名端口、线型、实际路径及可见箭尖；端口位于节点轮廓中部或专用端口，不能接容器、角点或空白。
- 使用 marker 时按其尖端位置计算目标轮廓外间隙；终点压在边框仍不合格。末段至少容纳箭头头部和清楚可辨的箭杆，不够时重排节点，不能让 marker 跨越折点或形成只剩三角形的连接。
- 反馈、条件旁注和主流各有独立通道。标签放在真实连续白区，与边界、折点、照片和箭杆隔开，按正文相同阅读下限核验；不以白框截断线路制造避让。灰虚线条件/反馈与蓝实线主流在全图及记录中保持一致。
- 生成者先完成渲染并停止写入，保存本轮文件摘要，再由主 agent 和独立审图 agent 检查同一稳定版本。独立审阅集中列出语义、排版、几何和阅读尺寸的全部硬伤；任何改动均重新导出并复核，不沿用旧图结论。历史失败稿和本次具体意见留在项目记录，通用规范不保存轮次、特定节点名或坐标。
