# 项目书技术路线图：审图模型全图转 HTML 重绘流程

本文档是“模型探索完整构图 → HTML/SVG 重绘 → 审图修改”的通用方法，与[项目书技术路线图：通用制作规范](<code_artifact.md>)并列。两种方法可独立使用；本文并非某次图件实验的复现指南。共同视觉风格保持一致，项目内容与布局由本次任务决定。

> **重绘质量优先**：模型探索成功不等于重绘成功。实际并排查看模型参考与 HTML 最终图，逐项记录参考中的哪些有效机制被保留、哪些错误被改正；若重绘只剩大框短句，必须重新设计，不能以“简化”为由丢掉主要机制。内容正确性始终以当前正文为准。

重绘前先完成插入尺寸预算和节点关系草图；反馈需经过真实校验节点，不能在容器之间的空白结束。完成后按本次阅读宽度查看最新 PNG；禁止自行假定超宽页面使小字看似达标。比较记录属于本次任务，不把项目宽度、字号值或版式固化为通用模板。

执行前必须完成 `code_artifact.md` 第 0 节的阅读尺寸预算、两种构图比较、图片语义分布与实际连接表。模型探索不能跳过后虚报；若服务失败，保留真实响应并明确采用人工构图。照片数量不能代替机制覆盖，主 agent 接管旧脚本修图不能算新的干净生成。

## 1. 本次输入

从当前对话与正文提取图的用途、必须保留的术语、输入输出、顺序/并行/映射/反馈/条件关系，以及确需展示的验证内容。确认插入尺寸、交付格式与可用工具，不预设图号、横向画布、三条主线或验证底栏。

项目路径、素材、提示词、模型和画布参数只属于本次任务。经验库不固化某份稿件、照片、服务安装路径、端口或模型名称。

## 2. 模型先探索完整构图

默认仅提供结构化文字和视觉约束，不上传原图、旧版图或项目素材，避免复刻旧布局。需要场景的位置让模型自行生成示意占位，现有素材在 HTML 重绘时再嵌入。用户本次明确指定对象参考时按要求使用，不能将独立对象参考偷换成整图版式参考。

提示词包含：

- 当前研究对象、图的用途和内容关系，不能把其他项目的模块名称当模板。
- 本次画布与信息密度要求；允许模型自由探索布局、主次区域与组件形状，不预设三列或上下总分。
- 白底、黑色直角大区块、浅蓝 `#B4C7E7`、深蓝 `#2F5597` 主流程、实虚线语义和字体层级；内部允许圆形、适度圆角和机制示意。
- 仅在内容需要时使用场景示意占位；不虚构实验结果、数据或随机照片。
- 箭头方向正确、无穿字进框、箭杆接三角形底边中央，避免线路打结。

模型图用于探索版式、层级、图文比例和机制呈现方式。先查看其是否满足内容与审美要求；不合格则修改提示词重新生成，不能为保留模型结果牺牲正文含义。模型图中的文字、箭头与科学关系不视为可靠事实。

## 3. 服务与工具调用

先启动项目根目录 `启动生图.sh`（Ubuntu/macOS）或 `启动生图.bat`（Windows），再打开 http://127.0.0.1:8765 。网页和客户端共用包内服务端，无需另行复制旧电脑的 `uuapi-image-web` 目录。经验库只存配置模板；个人下载包携带迁移自现有服务的本地配置。服务依赖 Python 3.9+ 和网络，上游模型可用性需实际调用确认。


使用当前可用的生图服务或工具，先核实其接口和输出格式；模型由本次任务选择，可在网页下拉框选择预置型号，也可手动输入上游支持的模型 ID。本文不要求特定供应商、模型或本机服务；不可用时如实说明，不把未调用说成已生成。

配套的 `UUAPI无素材生成.py` 仅适用于兼容以下契约的服务：`POST /api/generate`，请求字段为 `model`、`size`、`prompt`，响应提供 `images[0].url`。它不是通用供应商 SDK。地址、模型、尺寸均显式传参；配套完整本地网页服务与启动脚本见工具说明；默认本地地址为 `http://127.0.0.1:8765`，可通过启动参数更改。客户端不应填入上游 `/v1` 地址，因为两者接口不同。

若需要保留某个对象、设备或实验场景的主体特征，应使用 `参考图生图.py` 调用兼容 `POST /api/edit` 的服务。脚本将 1–4 张参考图编码上传，可附加蒙版，读取 `images[0].url` 后保存结果和 `result.json`。参考图只用于视觉 grounding；提示词必须要求新构图，并明确生成图不是实验结果。参考图、提示词、响应和生成版本留在本次项目目录，不复制进经验库。

在工具目录执行以下调用示例，将尖括号参数替换为本次实际值，不要原样运行：

```bash
python3 UUAPI无素材生成.py \
  --base-url '<本次服务地址>' \
  --model '<本次可用模型标识>' \
  --size '<服务支持的本次画布尺寸>' \
  --prompt '<本次提示词文件>' \
  --out-dir '<本次模型输出目录>'
```

该脚本不上传参考图。调用记录与模型图保存到传入的任务输出目录；凭据由所用服务管理，不写入经验库、提示词或脚本。

若服务安装目录曾迁移、重命名或移入回收站，须从当前包重新启动；已有进程的健康接口不证明其输出目录仍有效。使用实际生成、保存和下载结果验证新地址，分别记录本地落盘故障与上游请求故障，避免对失效进程重复生图。服务地址属于本次任务参数，不固定进通用规范。

## 4. HTML/SVG 重绘

1. 以合格的模型图作为构图参考，回到正文核对术语和关系；可进一步调整排版，不逐像素复刻模型错误。
2. 按当前尺寸创建画布与打印 CSS；文字、节点、箭头、机制图重新绘制为可编辑对象，不把模型整图放进 HTML 冒充重绘。
3. 按本次素材与用途替换场景占位。无对应素材且不需实物图的区域可改画机制示意，不强塞照片；记录真实/公开/生成性质。
   若路线图涉及实验设备、器皿、机器人或样本，按正文对象分布保留足够面积的实拍风格局部场景图；多对象实验路线不可只在同一输入区插两张缩略图，再用 SVG/HTML 绘制关系和箭头；照片只承担对象质感，不替代正文关系，也不使用带文字的整图生成结果。
4. 保持共同视觉风格，大区块直角，内部组件按语义灵活选形。多行 SVG 文字用独立文本或 `tspan` 布局。
5. 从节点边界和端口计算箭头，箭杆与三角形底边中央相接，尖端停在目标轮廓外；反馈、汇合和旁路留出清楚通道。
6. 项目文字、素材路径、坐标与版式脚本留在项目目录，不复制成经验库通用工具。

## 5. 渲染、审图与修改

### 5.0 实物图数量与分布专项审图

在独立审图前，主 agent 先打开最新整图，逐项标出每张对象级图片服务的正文机制。若所有图片集中在同一栏、同一排或只剩一个图片区，即使结构检查通过也判为不合格；应重新分配样本/容器、机器人/工具、培养设备、观测证据和执行场景等对象位。实物图可以是实拍、公开参考或单独生成的局部场景，但必须在记录中注明性质，图内不写“生成示意”。

审图时同时检查：图片主体是否可辨、是否被裁掉关键对象、是否与邻近文字重叠、是否在目标插入宽度下仍有足够面积；若“照片多但看不出对象”，应改用更贴合的局部素材而不是继续增加缩略图。图片分散后必须重新检查箭头通道和文字安全区，不能为塞图牺牲主流程端点或造成越框。

工具入口与参数见[README](<技术路线图_审图模型重绘/README.md>)。渲染工具只导出传入的 HTML，不决定内容、版式或纸张大小；打印尺寸由本次 HTML 的 `@page` 设置。

基础检查脚本仅核对 SVG 可解析性、HTML 中特定形式的 HTTP(S) 资产链接、指定标签及可选的单页 PDF。可选 `--font-class` 只检查 CSS 类声明与引用，以及别名误作字体族的常见错误；它不检查字体安装或实际字形，也不检查完整 CSS 依赖、文字碰撞、图片比例、箭头几何或科学正确性，不得将其通过描述为视觉验收通过。

实际查看最终整图与关键局部，检查内容、风格、图片、留白、文字层级与箭头端点，并按最终插入尺寸检查可读性。检查区域取决于本次图中实际存在的组件，不要求额外增加顶部反馈、三列主线或底部验证区。

独立审图 agent 按当前委派要求返图时，应同时获得正文内容摘要、有效风格要求和最终渲染图，严格检查内容与审美；不能只审源代码。将意见落实到源文件，重新渲染受影响区域并复查，不合格继续修改。报告真实执行的步骤，未返图或未复核的部分明确说明。

最终格式按本次要求确定。若要求原生可编辑 PPTX，另检查对象结构与实际渲染，HTML/SVG 可编辑不能代替 PPTX 验收。

审图返工应优先处理实际视觉关系：模块之间的留白是否均衡，图片、时间轴、事件卡和说明是否形成连续节奏；引线是否各自连接正确对象且互不交叉；反馈线是否沿独立旁路返回并落在目标边界；网络、箭头和标签是否互相避让。发现问题时要改动几何关系和连接路径，不能只删字、缩字号或移动单个标签。

一轮返工结束后，必须用最新 HTML 重新生成 SVG、PDF、PNG 及其他要求的格式，再把最新 PNG 交给审图 agent。审图结论只对该次渲染有效；重新调整坐标、线条或排版后，应重新审整组图，不能沿用上一版“通过”。

### 5.1 生成 agent 的硬性设计约束

委派生成 agent 时，任务中必须明确以下约束，并要求它在生成后实际查看整图：

1. 先从正文列出需要具象化的主要机制，再设计版式；神经网络/规程映射、设备协同、事件时间轴、状态恢复或培养周期只是可选类别，不能脱离正文硬塞。
2. 加入覆盖主要机制的可辨认图形（综合路线图应使用多种图形，简单图不固定数量），优先使用 SVG/HTML 绘制的小型网络、设备轮廓、容器、时间轴、状态环或拓扑图；对象级位图只能补充场景，不能把整张文字流程图当素材。
3. 不默认使用历史图的三块等高上下堆叠骨架；主模块允许不等高、左右协同、中心闭环或时间轴布局。文字删减后要重新分配空间，不能只缩字号。
4. 方法引导语、机制旁注和过程短句实际使用经核实的楷体（如 `AR PL UKai CN`、楷体或 KaiTi），并在渲染图中保留足够数量使字体层级可见；一级标题用黑体，正文/图注用宋体。
5. CSS 类名与字体族名分开处理：若使用 `.kai` 等类，文本通过 `class` 引用，不能写 `font-family="kai"` 冒充楷体；生成后搜索源文件并实际查看楷体文字。
6. 不在图内写图号、图题或“生成示意”等来源说明；来源、提示词和素材性质写入项目记录。
7. 生成完成后必须检查：整图、最终插入尺寸、机制图形数量、图文比例、楷体可见性、正文顺序、箭头端点、时间轴/标注线避让和图片与文字碰撞。任何一项不合格都要修改源文件并重新渲染。

### 5.2 代理闭环

本流程不是一次性委派：主 agent 先修改通用包中的约束或模板，不继承聊天记录、也不读取旧图绘制脚本的新 agent 再按最新包和本次正文生成；主 agent 亲自查看最新 PNG，记录具体失败模式（例如纯流程图、具象图形不足、楷体不可见或纵向过长），再回写通用包并开启下一轮。每一轮都要使用新的渲染结果，不能只复用旧截图或上一轮“通过”结论。

本轮复盘还需记录实现级失败：字体别名是否误用、机制图是否改变正文顺序、时间轴和反馈线是否穿过标签或接到角点、验证结论是否压住图形，以及版式是否只是把旧三栏改成不等宽。结构检查通过不能覆盖这些视觉和语义问题。

若使用带表头的大模块，额外检查表头下的首行基线和内边距：时间轴标题与刻度不得出现在表头区域；时间轴、事件卡、状态环应有清晰的垂直分层，不能在同一条水平带互相压叠。



### 端到端阶段门

- **输入门**：正文、插入尺寸、交付格式、素材性质和必须保留的关系已明确；缺失信息才提问。
- **探索门**：模型只负责探索完整构图、层级和图文比例；默认不上传旧整图。模型图的文字、箭头和科学关系必须回到正文核对。
- **素材门**：对象级参考图仅用于局部新素材生成；记录参考文件、提示词、模型、服务响应和视觉审查，失败请求也保留记录。
- **重绘门**：HTML/SVG 重新绘制文字、机制图和连接，图片离线嵌入；不把模型整图当成最终图或可编辑 SVG。
- **审图门**：先检查整图，再检查密集局部和实际插入尺寸；发现留白、拥挤、错线或语义问题时修改几何关系，重新导出并复审整组。
- **交付门**：只报告实际通过的检查；结构检查、视觉审图和 PPT 对象检查分别说明，不能用其中一项替代另一项。

## 6. 归档与可复用边界

两个平行文档分别保留直接制图规范与模型探索重绘方法，共享视觉风格但不互相强制流程。通用工具与依赖说明留在[README](<技术路线图_审图模型重绘/README.md>)所在目录，项目产物留在本次指定的输出目录。

通用工具不携带任何项目的固定路径、照片、正文、布局坐标或 API key。工具接口依赖如 UUAPI 请求契约、浏览器和 PDF 命令应明确说明，不伪装为跨环境自动适配。项目专用脚本不作为通用工具归档。

### 5.3 小型节点和长反馈线的专项门

菱形、圆形等小型机制节点先建立文字安全内框，文字与斜边/圆周保持可见间隙；连接线接节点边界中部或预留端口，不得落在卡片角点、斜边或两行文字上。跨模块证据回写使用独立侧边通道，避开模块底边、验证区和事件卡文字。生成 agent 必须先完成并关闭写入，再交付最终 PNG；审图 agent 不得依据仍在变化的中间文件给出通过结论。

新的生成 agent 只接收包、当前正文与输出路径；主 agent 的修正意见先归纳进包，不能用额外的图件专用设计提示替包弥补缺失。独立审阅需以最终文件的稳定版本为准，并复核箭头是否悬空、超短、压字，以及照片是否被重复矢量对象遮挡。

每次返工还须执行 `code_artifact.md` 的“从失败样稿进入新一轮”：先比较不同构图，再明确机制图实际表达的关系，并记录连接端口。不得把照片加进被否决的旧骨架就称为新设计。语义连接必须在校验、执行、证据和恢复之间保持正文顺序；不能让箭头在目标附近的空白停止。


**素材真实性门**：生成图片必须在项目记录标为“生成示意”，不得在图内写来源，也不得把插画/线框称为实拍；若用户要求实拍风格，必须检查纹理、光照和真实设备比例，未达到时应报告限制。


### 内容范围与真实阶段记录

新 agent 的输入必须包含：通用包、唯一正文文件及本次图所在章节、输出目录；可选素材目录和质量标杆均是本次输入，不写入通用规范。若主 agent 未提供唯一正文，不应自行换成另一个全项目压缩包；先核对已有输入。

先完成 `code_artifact.md` 的“内容与构图验收”，再进行模型探索。禁止为让流程显示成功而更换研究主线、用装饰环路代替机制或用 SVG 场景冒充实拍风格位图。完整模型探索与局部素材生成是两个独立步骤，分别保存提示词、实际模型、响应与结果。失败记录必须保留服务响应正文，不能只记录“502”。模型探索失败时可继续人工构图，但阶段记录必须写明跳过了哪一步，不能声称完成全流程实验。

已有本次输入中的合适局部生成素材可直接用于 HTML 重绘，无需反复调用；素材图与旧整图严格区分。最终 HTML 和 SVG 都须自包含实际位图（例如 data URI），不能仅 HTML 内嵌而 SVG 仍指向本机图片路径。基本结构检查与独立视觉审图分开报告，最终以最新渲染图验收。


### 最终阅读尺寸与几何验收

构图前按本次插入宽度预算正文大小和图片面积，内容超预算先缩减重复说明和改变分区，禁止将研究段落塞进十余张小卡片后整体缩小。一级区块保持黑色直角边界，主流用深蓝，照片具有可辨认面积，图片不能挤在验证栏角落。

最新 PNG 审图应逐条判断：小字在实际插入尺寸能否读清、照片是否可辨对象、层级任务图与候选映射是否实际用图形表达、事件轴是否有真实内容、恢复线是否避开其他节点、是否残留标题/图题/图片说明/配色代码等禁项。失败版本只归档，不把“已打开图片”写成“视觉通过”。


### 闭环与时间轴端点专项
- 正文要求闭环时，主路径必须回到规定的起点。执行类闭环不能遗漏“执行 → 结果证据”；不能只画证据向后流动而缺失执行回写。具体节点与校验顺序由当前正文确定，不固定模块名称或数量。
- 时间轴或验证链的箭头从源节点轮廓连接到下一节点轮廓，不能止于两节点之间的空白。用于连续时间方向的轴线除外，应明确区别轴线与节点关系。
- 端口表必须与最终 SVG 实际路径一致；若源脚本和渲染结果不一致，以最新 PNG 重新审查，不得沿用旧端口声明。
- 模块布局拥挤时，重新分配主机制的面积并预留跨模块通道。先计算文字安全区域和端口，再绘制连接；少量有依据的主要节点优于反复叠加概述框。结构修复和全新独立生成分别记录，不将主 agent 接管修图当作开箱包一次生成通过。

### 对标与稳定交付的复核门

模型探索、HTML 重绘与独立审阅分别记录实际执行情况。探索失败可转人工构图，但不能称为完整模型流程或一次生成成功；结构修复与干净 agent 的独立生成也须区分。

- 标杆用于比较机制清晰度、对象图主体、视觉重心和实际阅读尺寸。先看图形是否解释了正文，再看字体和几何；多放照片不能弥补层级拓扑、映射或依赖恢复的缺失。
- 同一线路反复失败时重新分配节点和通道，不在错误间距内不断挪端点。反馈与主流各用独立端口，旁注另有安全区；不得以短 U 回折、角点接线、白色遮罩或只剩三角形的箭头通过验收。
- 从输入沿实际箭头追踪到输出。校验、确认、执行、证据和恢复仅在正文需要时出现，出现时须连接真实节点。检查源目标语义和几何同时一致，不能将指向一个任务的线在端口表写成另一个任务。
- 恢复区用真实依赖边区分保留事实和受影响的未执行后继；无可行方案才产生冲突反馈。照片、状态词和旁注不能代替该机制。
- 节点、端口、路径和连接表同源导出，按 marker 实际尖端核验外部间隙和可辨箭杆。文字检查覆盖全部实际字号和完整边界，包含时间刻度、旁注、跨栏长句与非矩形节点；以最终打印尺寸验证，不能以像素分辨率替代。
- 冻结后保存本轮文件摘要，主 agent 与独立审图 agent 只审同一稳定版本；审阅一次集中列出全部硬伤。修改后重新导出及复核，不沿用上一版通过结论。图件特定路径、坐标、轮次与失败细节留在任务目录，通用方法不写死这些信息。
