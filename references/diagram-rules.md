# 机制图与配图规则

## 1. 一条关系 = 一条折线

- 转弯必须用**一条连续折线**，只在终点放一个箭头；不能在拐角处出现箭头。
- 禁止用多条 `STRAIGHT` connector 拼成一条折线；那会在拐角留下断头箭头，读成多条边。
- 引擎提供 `connectors.add_polyline(slide, [(x1,y1), (x2,y2), ...])`：原生可编辑、单终点箭头。
- 审查必须沿每条关系从头走到尾；中间出现箭头、线条错位、悬空端点，都算必须改。

## 2. 图片必须回答“多了什么信息”

- 图注写什么，图里就必须有什么；图注说“状态/时点”，画面就得看见状态或时点。
- 通用机器人/器材场景不能当状态证据；只能标“场景示意”，且不占证据位。
- 如果图片不增加文字没有的信息，删掉；空出来的位置给状态快照表/证据字段，不硬塞。

## 3. 色彩要有角色，不是四张卡四色

- 每页最多两个中性面（纸底/卡片）+ 一个主强调色；语义色只给状态。
- 同一语义不能一色两义：警示底色不能同时当普通卡底。
- 2×2 卡不能四种底色；要么统一，要么按行/列两色交替，并说明理由。
- P5 四柱等权时，必须有分组/阶梯/对照隔断，不能四根同权并列。

## 4. 审查审美项

视觉审查除重叠/字号/留白外，必须写：

- 主色/辅助色/语义色分别用在哪；
- 折线是否连续、拐角有没有多余箭头；
- 图片与图注是否一致、图片有没有信息角色；
- 阶梯/分组是否真的在版式上成立。

不能用“投影差异很小”“可接受”豁免一条已列出的审美必须改；要豁免必须给出度量或明确降级理由。
